# kimitoboku.github.io

## Development

### Prerequisites

- Docker
- Docker Compose

### Build and Run

```bash
# Start development server
docker compose up

# Run in background
docker compose up -d

# Stop server
docker compose down
```

The site will be available at http://localhost:4000

Live reload is enabled - changes will automatically refresh the browser.

Each post is also published as its raw Markdown source by appending `.md` to
the post URL. For example:

```text
/archive/2026/01/01/best-movie.md
```

This endpoint is generated by `_scripts/generate_raw_posts.rb`. Production
deployment therefore uses the custom GitHub Pages workflow in
`.github/workflows/pages.yml`.

### OGP images

The production workflow generates a 1200 x 630 PNG for every post and passes
its path to `jekyll-seo-tag`. Generated images are published below
`/image/ogp/`. A post with an explicit `image` value in its front matter keeps
that image instead of receiving a generated one.

`docker compose up` generates the images before starting Jekyll. Restart the
container after changing a post title to refresh its image. To generate the
assets manually:

```bash
docker compose run --rm jekyll sh -lc \
  'bundle exec ruby _scripts/generate_ogp_images.rb --config .jekyll-cache/ogp.yml --output _site &&
   bundle exec jekyll build --config _config.yml,.jekyll-cache/ogp.yml'
```

### Rebuild

```bash
# Rebuild after Gemfile changes
docker compose build --no-cache

# Rebuild and start
docker compose up --build
```
